## 3. 数据模型 / 配置

### 3.1 config.db 新增字段

```sql
-- key = "upload_secret"
-- value = "7f3a9b2c8e1d4f6ab2c8e1d4f6ab2c8e"（32 字符 hex）
-- 写入时机：
--   1. UploadServerService 构造时（如不存在）
--   2. UI 点「重置密钥」时（覆盖）
--   3. 校验失败被外部篡改时（重新生成 + 写回）
```

**字段约束**：

- 类型：TEXT（key=value 都是 TEXT，沿用 `config` 表结构）
- 长度：严格 32 字符
- 字符集：`^[a-f0-9]{32}$`（小写）
- 加密：明文（家庭 LAN 风险可控）

**迁移策略**：

- **v0.12 → v0.14**：自动。`upload_secret` 不存在 → 启动时生成 + 写。
- **同 PC 同时持有多版本**：以最新一次启动的版本为准（无版本号元数据，db 读啥用啥）。
- **手动清 `upload_secret`**：下次启动视为「新装」，重新生成。
- **db 字段被外部篡改为非法 hex**：启动时校验失败 → 重生成 + 覆盖写回。

## 4. UploadServerService 改动细节

### 4.1 字段重命名

```csharp
// v0.12
private string _currentToken = GenerateToken();
public string CurrentToken => _currentToken;
public event Action<string>? OnTokenChanged;

// v0.14
private string _currentSecret = LoadOrGenerateSecret();
public string CurrentSecret => _currentSecret;
public event Action<string>? OnSecretChanged;
```

### 4.2 LoadOrGenerateSecret 逻辑

```csharp
private string LoadOrGenerateSecret(IConfigService configService)
{
    // 1. 读 db
    var stored = configService.GetAsync<string>("upload_secret").GetAwaiter().GetResult();
    if (!string.IsNullOrEmpty(stored) && IsValidSecret(stored))
        return stored;

    // 2. 不存在 / 非法 → 生成 + 写回
    var fresh = GenerateSecret();
    configService.SetAsync("upload_secret", fresh).GetAwaiter().GetResult();
    Debug.WriteLine($"[UploadServer] upload_secret initialized: {fresh}");
    return fresh;
}

private static bool IsValidSecret(string s)
{
    return !string.IsNullOrEmpty(s)
        && s.Length == 32
        && Regex.IsMatch(s, "^[a-f0-9]{32}$");
}

private static string GenerateSecret()
{
    var bytes = new byte[16];
    RandomNumberGenerator.Fill(bytes);
    return Convert.ToHexString(bytes).ToLowerInvariant();
}
```

> 注：构造期同步读 db 是 v0.12 既有用法（`_currentToken = GenerateToken();` 也是同步）。构造期用 `.GetAwaiter().GetResult()` 不会死锁（无 SynchronizationContext）。

### 4.3 ValidateSecret（替换 ValidateToken）

```csharp
private bool ValidateSecret(HttpListenerRequest request)
{
    // 优先 query 参数 ?k=
    var secret = request.QueryString["k"];
    // 备选 header X-Key
    if (string.IsNullOrEmpty(secret))
        secret = request.Headers["X-Key"];
    return !string.IsNullOrEmpty(secret) && secret == _currentSecret;
}
```

> **保留 query/header 双通道**：query 优先。`?token=` / `X-Token` 老字段不识别（KB 已规定 v0.13+ 忽略）。

### 4.4 RegenerateSecret（替换 RegenerateToken）

```csharp
public void RegenerateSecret()
{
    var fresh = GenerateSecret();
    _currentSecret = fresh;
    _configService.SetAsync("upload_secret", fresh).GetAwaiter().GetResult();
    OnSecretChanged?.Invoke(_currentSecret);
    Debug.WriteLine("[UploadServer] Secret regenerated and persisted to config.db");
}
```

### 4.5 StartAsync 调整

```csharp
// v0.12 旧代码
OnTokenChanged?.Invoke(_currentToken);

// v0.14
OnSecretChanged?.Invoke(_currentSecret);
```

### 4.6 HealthResponse 构造点

### 5.2 BuildDisplayUrl（QR 内容生成）

```csharp
// v0.12
private string BuildDisplayUrl()
{
    var host = LocalAddresses.Count > 0 ? LocalAddresses[AddressIndex] : GetLocalIp();
    return $"{_server?.UploadUrl?.Replace($"http://{GetLocalIp()}:{Port}", $"http://{host}:{Port}")}?token={CurrentToken}";
}

// v0.14
private string BuildDisplayUrl()
{
    var host = LocalAddresses.Count > 0 ? LocalAddresses[AddressIndex] : GetLocalIp();
    var baseUrl = $"http://{host}:{Port}";
    var mode = PublicRelayViewModel?.IsRunning == true ? PublicRelayViewModel.PublicUrl : baseUrl;
    return $"{mode}/upload?k={CurrentSecret}";
}
```

> 关键变化：`?token=` → `?k=`（KB API-04-qr-protocol.md §1.1）。

### 5.3 StartServer 订阅改名

```csharp
// v0.12
_server.OnTokenChanged += token => Dispatcher.UIThread.Post(() =>
{
    CurrentToken = token;
    StatusMessage = $"Token 已刷新：{token}";
});

// v0.14

{
    CurrentSecret = secret;
```

### 5.4 RegenerateSecretCommand（替换 RegenerateTokenCommand）

```csharp
[RelayCommand]
private void RegenerateSecret()
{
    _server?.RegenerateSecret();
}

// MaskSecret：12****56 形式（KB §十六）
private static string MaskSecret(string s)
{
    if (string.IsNullOrEmpty(s) || s.Length < 8) return "****";
    return $"{s[..4]}****{s[^4..]}";
}
```

### 5.5 NetworkChange 监听（v0.14 新增）

> KB 00-pc-app.md §2.3 要求；当前 v0.12 代码未实现。

```csharp
private void SubscribeNetworkChange()
{
    NetworkChange.NetworkAddressChanged += OnNetworkAddressChanged;
}

private void UnsubscribeNetworkChange()
{
    NetworkChange.NetworkAddressChanged -= OnNetworkAddressChanged;
}

private void OnNetworkAddressChanged(object? sender, EventArgs e)
{
    Dispatcher.UIThread.Post(() =>
    {
        // 1. 黄色提示条
        ErrorMessage = "网络 IP 已变，请重新扫码";
        // 2. 刷新 QR host（secret 不变）
        RefreshQrForCurrentAddress();
        Trace.WriteLine("[UploadServerVM] NetworkAddressChanged, QR host refreshed");
    });
}
```

**生命周期**：

- `StartServer` 末尾 → `SubscribeNetworkChange()`
- `StopServer` 末尾 → `UnsubscribeNetworkChange()`

## 7. 关键流程

### 7.1 启动时 secret 加载

```
UploadServerService 构造
   ↓
LoadOrGenerateSecret(_configService)
   ├─ IConfigService.GetAsync<string>("upload_secret")
   │     ├─ 存在 + 合法 → 返回
   │     ├─ 存在 + 非法（被篡改）→ 重生成 + 覆盖写
   │     └─ 不存在 → 生成 + 写回
   ↓
_currentSecret = loaded
```

### 7.2 重置密钥

```
UI 点「重置密钥」
   ↓
UploadServerViewModel.RegenerateSecret()
   ↓
UploadServerService.RegenerateSecret()
   ├─ GenerateSecret() → 新 32 hex
   ├─ _currentSecret = new
   ├─ IConfigService.SetAsync("upload_secret", new) → 写回 db
   └─ OnSecretChanged?.Invoke(new)
        ↓
        VM.CurrentSecret = new
        VM.StatusMessage = "密钥已刷新：12****56"
        VM.RefreshQrForCurrentAddress() → QR 刷新
```

### 7.3 App 端扫码（验证持久化效果）

```
第一次扫码（v0.14 新装）
   ↓
config.db.upload_secret 为空
   ↓
生成 secret + 写回 db
   ↓
App 端扫码拿到 secret → 进空间列表 → 正常用

PC 重启（关键验收）
   ↓
UploadServerService 构造 → LoadOrGenerateSecret
   ├─ db 中已有 → 复用同一 secret
   ↓
App 端 health 200 → projects 仍可用 secret → 无 401 → 无需重扫 ✓
```

### 7.4 IP 变化

```
NetworkChange.NetworkAddressChanged 触发
   ↓
UploadServerViewModel.OnNetworkAddressChanged
   ├─ ErrorMessage = "网络 IP 已变，请重新扫码"（黄色提示）
   └─ RefreshQrForCurrentAddress → QR host 字段刷新（secret 不变）
   ↓
App 端（旧空间）
   ├─ 下次 health 请求仍成功（IP 是新的但 secret 没变）→ 进主页？
   ├─ 答：❌ App 端会失败，因为 App 持久化的 IP 已是旧 IP
   └─ App 端 health 失败 → 提示「连不上 PC」→ 引导重扫
```

> 注：IP 变化会让 App 端旧的 IP 失效，但 secret 仍然有效。App 端只需「重新扫码」（拿到新 IP）即可继续工作。

## 8. 边界情况处理

| 场景 | 行为 |
|------|------|
| `config.db.upload_secret` 不存在 | 启动生成 + 写 |
| `config.db.upload_secret` 非法（非 32 hex） | 启动校验失败 → 重生成 + 覆盖写 |
| `config.db.upload_secret` 为 null | 同上 |
| `config.db` 文件被锁 / IO 失败 | 启动失败 → 抛异常（与 v0.12 行为一致） |
| UI 重置密钥时 db 写入失败 | 抛异常 → UI Toast 错误；当前内存 secret 已变（不等同于磁盘值）→ **下次启动会回滚到磁盘旧值**。**需要明确提示用户** |
| 多实例 PC（同时启两个 PC 进程） | 共享同一 `config.db.upload_secret` → 后启动的覆盖写？需要分析：是 `INSERT OR REPLACE` 语义，安全 |
| UDP 广播 / 局域网嗅探 | 与 v0.12 一致（明文）；家庭 LAN 风险可控 |
| App 端 secret 失效（v0.12 兼容） | `?token=` 不识别 → 401 invalid secret；App 端 401 → 引导重扫 |
| 旧 v0.13 PC（持久化但格式不同） | 无此场景（v0.13 仅在 KB，未发布代码） |

### 10.3 性能 / 安全

- 启动时间影响：`LoadOrGenerateSecret` 仅一次 SQLite `SELECT`（< 5ms）+ 偶发 `INSERT`（< 50ms）
- 内存影响：无（仅一个 string 字段）
- 网络：UDP 广播 payload 增大（6 位 → 32 字符 + 字段名 token → secret 共 ~26 字节），仍在 1.5KB 内无影响

## 12. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| `_currentSecret` 公开 API 破坏性变更 | 上层依赖 `CurrentToken` 的代码（如未来插件）编译失败 | 当前仓库内已识别全部引用点；CI 构建可拦截 |
| v0.12 PC + v0.14 App 不兼容（App 用 `?k=`，PC 仅认 `?token=`） | App 端 401 | KB 已要求两端同步升级；提供降级路径说明 |
| `config.db.upload_secret` 被外部清空 | 下次启动重生成 → 所有已扫码 App 401 | 极少数用户操作；启动日志明确打印 |
| UDP 广播字段 `token → secret` 不向后兼容 | v0.12 App 通过 UDP 发现但用 `token` 字段 | v0.12 App 不存在（v0.12 协议未对外发布 App） |
| 同步 `GetAwaiter().GetResult()` 在 UI 线程构造 service 时死锁 | 启动卡死 | UploadServerService 构造不在 UI 线程（VM 构造时同步 new），无 SynchronizationContext |
