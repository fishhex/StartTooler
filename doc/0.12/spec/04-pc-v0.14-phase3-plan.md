## Step 3: 持久化端到端验证

### 3.1 场景 A：新装（无 upload_secret）

```bash
# 1. 清 config.db（或删文件）
rm ~/.config/StartTooler/config.db  # 路径按实际调整

# 2. 启动服务
dotnet run --project StartTooler

# 3. 验证 db 有 upload_secret
sqlite3 config.db "SELECT key, value FROM config WHERE key='upload_secret'"
# 期望：upload_secret|<32 hex>

# 4. 验证 health 返回 secret
curl -s http://localhost:8765/api/v1/health | jq .secret
# 期望："<32 hex>"（与 db 一致）
```

### 3.2 场景 B：重启复用（v0.14 关键验收）

```bash
# 接 3.1
SECRET=$(curl -s http://localhost:8765/api/v1/health | jq -r .secret)

# 停服务
# Ctrl+C / dotnet stop

# 启动服务（再次）
dotnet run --project StartTooler

# 验证 secret 不变
SECRET2=$(curl -s http://localhost:8765/api/v1/health | jq -r .secret)

[ "$SECRET" = "$SECRET2" ] && echo "✓ secret persisted" || echo "✗ secret changed"
```

### 3.3 场景 C：projects 端点鉴权

```bash
SECRET=$(curl -s http://localhost:8765/api/v1/health | jq -r .secret)

# 正确 secret → 200
curl -sw "\n%{http_code}\n" "http://localhost:8765/api/v1/projects?k=$SECRET"

# 错误 secret → 401
curl -sw "\n%{http_code}\n" "http://localhost:8765/api/v1/projects?k=wrong"

# 旧字段 token → 401（v0.14 不识别）
curl -sw "\n%{http_code}\n" "http://localhost:8765/api/v1/projects?token=$SECRET"

# X-Key header → 200
curl -sw "\n%{http_code}\n" -H "X-Key: $SECRET" "http://localhost:8765/api/v1/projects"
```

期望：

| 请求 | 期望状态码 | 期望响应 |
|------|------|------|
| `?k=$SECRET` | 200 | `{ "projects": [...] }` |
| `?k=wrong` | 401 | `{ "error": "invalid secret" }` |
| `?token=$SECRET` | 401 | `{ "error": "invalid secret" }` |
| `X-Key: $SECRET` | 200 | `{ "projects": [...] }` |

### 3.4 场景 D：重置密钥

PC 端 UI 点「重置密钥」：

```bash
SECRET_OLD=$(sqlite3 config.db "SELECT value FROM config WHERE key='upload_secret'")
# UI 点重置密钥
SECRET_NEW=$(sqlite3 config.db "SELECT value FROM config WHERE key='upload_secret'")

[ "$SECRET_OLD" != "$SECRET_NEW" ] && echo "✓ secret regenerated" || echo "✗ secret unchanged"
[ ${#SECRET_NEW} -eq 32 ] && echo "✓ length=32" || echo "✗ length wrong"

# 旧 secret 应 401
curl -sw "\n%{http_code}\n" "http://localhost:8765/api/v1/projects?k=$SECRET_OLD"
# 期望：401
```

## Step 4: 与 App 端兼容性

### 4.1 App 端不存在（v0.13+ 未发布）

当前仓库没有 App 端代码（iOS / Android / macOS 客户端）。**完整 App 端验证需要后续阶段**。

### 4.2 模拟 App 端验证

用 curl 模拟 App 端完整流程：

```bash
# 1. 健康检查（无需 secret）
HEALTH=$(curl -s http://localhost:8765/api/v1/health)
echo "Health: $HEALTH"

# 2. 解析 secret
SECRET=$(echo $HEALTH | jq -r .secret)
NAME=$(echo $HEALTH | jq -r .name)

# 3. 拉项目列表
PROJECTS=$(curl -s "http://localhost:8765/api/v1/projects?k=$SECRET")
echo "Projects: $PROJECTS"

# 4. 上传一张图
FIRST_PROJECT=$(echo $PROJECTS | jq -r '.projects[0].name')
curl -s -X POST "http://localhost:8765/api/v1/projects/$FIRST_PROJECT/upload?k=$SECRET" \
  -F "file=@/tmp/test.jpg"

# 5. PC 重启后重复步骤 1-4，验证 secret 复用
```
